## Stage 0: is self-play limited by the CPU or the GPU? (measured)
- **CPU side** (SPRT 8, 800 PUCT-vs-PUCT games, dev levels = 2-player Capitals 11×11, Fog, git d83843f):
  794 decisions per game (both players), 81.8 s per game on one thread, 0.103 s per decision.
  With 2,000 expansions per decision, that's ~51 µs per expansion, including Rule Based scoring and the Diff leaf.
- **GPU side** (scratch ResNet benchmark, fp16, channels-last, cuDNN benchmark mode, 64 input planes, a 332-channel
  policy conv + 131-way global head, A2000 Laptop 4 GB, torch 2.14.0+cu130). Positions/s at batch 1024
  (batch 256 is within 15%):

| trunk (channels × blocks) | 11×11 | 16×16 | 24×24 |
|---|---|---|---|
| 32 × 4 | 193,510 | 94,945 | 42,773 |
| 64 × 6 | 79,841 | 37,957 | 16,641 |
| 96 × 8 | 33,628 | 15,163 | 6,629 |

- **Consequence:** with one network evaluation per expansion, a game at 2,000 per decision is ~1.6M
  evaluations. That's ~20 s of GPU time for 64 × 6 on 11×11 → ≤ ~180 games/h, whatever the CPU does.
  So the GPU, not the CPU, bounds self-play at this budget.
  - **Correction** to what I told the user earlier today ("the CPU is the bottleneck, a bigger GPU alone
    won't help much"): that was true of search without a network, not of network-guided search.
  - **Levers:** fewer expansions per self-play decision, a smaller trunk, running the net at the map's own size
    (11×11, not the 24×24 frame), and batching ≥ 256 leaves at a time.
  - These are compute estimates. End-to-end games/h is still `[TBD]`.
