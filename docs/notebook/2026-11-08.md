# 2026-11-08

## Simulator benchmark (Phase 1 DoD: benchmark vs. Tribes' forward model)
- Design: `OracleBench.java` (in `core.game` for the package-private turn methods) runs OracleDriver's loop
  without logging, a uniform pick from `getAllAvailableActions()` of the true state (RandomAgent minus the
  per-decision `gs.copy`), and writes each level; `tools/bench.cpp` loads the same levels and runs the same loop,
  including Tribes' stale `continueTurn` (decided before the chosen action runs) so decision counts match.
  Only the loop is timed. `oracle/scripts/bench.py` runs configs one at a time; `make bench N=`.
- Check that both sides do the same work: decisions/game agree within 3% in all 6 configs (2/4/8 players ×
  Capitals/Score), same end tick (51 / 31). 24 random playouts (2–8 players, both modes) clean under ASan/UBSan.
- Java warm-up: 50, 300, 1,000 warm-up games → 12.4k, 10.1k, 12.4k decisions/s (2 players): 50 is enough.
- **Run-to-run noise:** the first two 200-game runs of identical games differed by up to ±50% in absolute rate
  (e.g. ours, 2p Score: 171k vs. 90k decisions/s). The ratio moved less. → 3 runs at `c2507a2`, report the
  median and the min–max; `plot_bench.py` takes several CSVs (median bars, min–max whiskers).
- **Result:** speedup 5.3–6.3× median per config (per-run range 4.4–7.2×); ours 81k–141k decisions/s,
  Tribes 18k–24k. Media: `docs/media/2026-11-08-sim-speed.png` + sidecar (full table, provenance).
- Tooling: `make setup` now creates `.venv` (matplotlib, ruff; `requirements.txt`); `make plots` draws the chart.
  ruff on the older scripts finds 6 pre-existing issues (`re.M` alias, `subprocess.run` without `check`); not
  fixed yet, and ruff isn't in CI yet.
- No bugs found.
