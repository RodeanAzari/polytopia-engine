## Agent facts sheets 01 (common + Diff heuristic) and 02 (MCTS)
Extracted from the Tribes source (facts only). Things that differ from what the paper led us to expect:
- Root prioritization picks the action group **once per decision call**, not per iteration (paper sheet fixed).
- The unit group keeps **Disband** (filtered into an unused list); the city group drops Destroy.
- MCTS's budget counts **UCT descent steps** as forward-model calls, so an iteration expanding at depth d costs d.
- Opponent nodes **minimise** UCT value including the exploration term.
- Diff's visible-tiles term counts the vision of the tribe **active** in each state, not the searcher's; its
  unit count includes only city-attached units. Under full obs the vision term is always 0.
- Root choice: most visits, unless all expanded root children are tied, then best mean.
No bugs (no code written).

## Agent-side forward model (rule facts 04 §9) and its difftest
Tribes' search agents simulate with `GameState.advance` on a copy of their observation, not the game loop
(no tick increase, game-over only at End Turn, next tribe = first not *lost*). New: `poly::agent_advance`;
`OracleDriver --probe=N` logs, every N-th decision, 30 random `advance` steps on `obs.copy()` (End Turn with
p = 0.2, a seeded logging RNG on the copy: PRAND); `oracle_diff` replays them on our observation and compares
every state and legal set; `make difftest-fm`. Bugs found (all in rules running on a non-native copy, which
the replay/OBS difftests never exercise):
1. Symptom: hidden tribe +5 score / gains a connected city after a road. Root cause: Tribes' non-native board
   recomputes only the active tribe's network and never eliminates (03b, already documented as "our sim is
   always native"). Fix: `GameState::native` (false in observations), both rules honour it.
2. Symptom: connected-cities order differs ([5, 9, 138, 22, …]). Root cause: a hidden tribe's city list in the
   copy is in Java HashMap order (id mod bucket count), ours in slot order; the dump sorts the list, so the
   OBS difftest couldn't see it. Fix: `actor_map_capacity` tracked on the native state (16, ×2 above 3/4 live
   cities + units), observation sorts by (id & (cap−1), id).
3. Symptom: our sim aborts "build: illegal" at a probe's first step. Root cause: the root actions are the
   environment's (true-state) legal set; a Zebasi Farm (Farming without Organization) is legal there but
   crops are masked in the copy; Tribes executes nothing **and keeps its stale cached legal list** (it
   recomputes only after an executed action). Fix: `agent_advance` returns whether it executed; callers keep
   their list otherwise.
4. Partial obs, symptom: extra meeting-tech draw. Root cause: a ghost city (tribe −1) on a fogged tile was
   "met" (and indexed tribes[−1]: UB). In Tribes' copy that city isn't an actor. Fix: skip ghosts in meetings.
5. Partial obs, symptom: hidden opponent's boats have fewer moves. Root cause: Fog tiles cost 1 for naval
   units in Tribes; ours charged the rest of the allowance. Fix in `step_cost`.
6. Partial obs, symptom: hidden tribe +20/tile after village capture / border growth. Root cause: a fogged
   tile's owner is city id 0 (owned, by no actor), ours was "unowned", so borders claimed it. Fix: one phantom
   ghost city (id −1) owns every fogged tile; the old unit test expected "unowned" and was wrong per 04 §7.
Unit tests for each (bug injection: every injected variant caught).
Process slip: I ran `git stash` twice while a background difftest was running (it briefly restored the old
corpus script, which drops `--probe`); harmless here (fewer probes, no false pass) but don't stash mid-run.
7. Full obs, 1 game in 200, symptom: Park of Fortune buildable for a hidden tribe after a Park level-up.
   Root cause: its monument map is empty in the copy; unlocks need "unavailable" (null fails), ours defaulted
   to Unavailable. Fix: `MonumentStatus::Absent` for hidden tribes; the dump omits absent entries.
