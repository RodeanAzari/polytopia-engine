## Agent facts sheets 01 (common + Diff heuristic) and 02 (MCTS)
Extracted from the Tribes source (facts only). Things that differ from what the paper led us to expect:
- Root prioritization picks the action group **once per decision call**, not per iteration (paper sheet fixed).
- The unit group keeps **Disband** (filtered into an unused list); the city group drops Destroy.
- MCTS's budget counts **UCT descent steps** as forward-model calls, so an iteration expanding at depth d costs d.
- Opponent nodes **minimise** UCT value including the exploration term.
- Diff's visible-tiles term counts the vision of the tribe **active** in each state, not the searcher's; its
  unit count includes only city-attached units. Under full obs the vision term is always 0.
- Root choice: most visits, unless all expanded root children are tied, then best mean.
No bugs (no code written).

## Agent facts sheets 03 (OSLA, MC) and 04 (RHEA)
- OSLA: no root groups; skips End Turn/Destroy/Disband, so it ends its turn only when nothing else is legal.
- MC: before each rollout gives every opponent ⌊tick/2⌋ free random techs in the copy (their trees are hidden);
  rollouts never pick End Turn voluntarily; "best" is a running record of means, not the final argmax; budget
  check is ≥ 2,000 (MCTS: > 2,000).
- RHEA (pop 1): plans span both players after an End Turn; **shift doesn't truncate an infeasible tail**: random
  actions are appended after it, so the stored plan differs from the evaluated one, plans can grow by up to 19
  per shift, and an infeasible first action can be returned. Tribes treats an infeasible returned action as a
  no-op and asks again (all 23 commands check feasibility first); our tournament runner must do the same.
